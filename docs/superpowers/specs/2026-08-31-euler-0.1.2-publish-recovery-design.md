# Euler 0.1.2 发布恢复设计

## 问题

`smoke-test-binaries` 会创建平台专属的标记文件，例如
`smoke-ok-windows-x64.txt`，但上传步骤固定查找 `smoke-ok.txt`。
所有标记因此丢失，后续发布阶段无法验证 Windows x64 的冒烟结果，npm
发布不能开始。

## 方案

1. 上传步骤使用与创建步骤一致的平台专属文件名
   `smoke-ok-${{ steps.binary.outputs.platform }}.txt`。
2. 保持标记的 artifact 名称、后续下载模式及 Windows x64 硬性发布门槛不变。
3. 提交工作流修复到 `main`。
4. 使用已有的 `v0.1.2` 作为发布标签、最新 `main` 作为源码引用手动派发
   `Build Binaries`。不创建新版本、不移动现有标签、不重新运行本地发布脚本。

## 验收

- 各平台成功时均上传对应的 `smoke-ok-<platform>.txt`。
- `stage-github-release` 能下载 `smoke-ok-windows-x64.txt`。
- `publish-npm` 完成后，`npm view euler-agent@0.1.2 version` 返回 `0.1.2`。
