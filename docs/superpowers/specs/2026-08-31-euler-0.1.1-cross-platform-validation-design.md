# Euler 0.1.1 cross-platform validation

## Goal

Make the Euler source test suite runnable on Linux and Windows without masking real failures, then release the fixes as `0.1.1`. The published `0.1.0` packages remain unchanged.

## Scope

1. Parse POSIX external-editor commands with quoted executable paths correctly. A command such as `"/usr/bin/node" fixture.mjs` must start Node instead of attempting to execute a filename containing quote characters.
2. Make Euler web-access tests platform-neutral. The tests will derive expected path separators and browser launch commands from the active platform instead of hard-coding Windows-only values.
3. Keep permission tests meaningful by documenting and using a non-root Linux test user. Root bypasses POSIX write permissions, so it cannot validate `EACCES` behavior.
4. Treat `rg` and `fd` as required Linux test prerequisites. Tests should exercise the actual search tools rather than silently skipping them.

## Non-goals

- No change to the public `euler` command surface or web-search workflow.
- No change to npm package names, package scope, or telemetry policy.
- No rewrite of unrelated upstream tests.

## Implementation

- Add a small internal parser for editor command strings used on POSIX, supporting quoted executable paths and normal whitespace-separated arguments.
- Update the external-editor tests with Linux coverage for quoted paths.
- Update web-access unit tests to calculate their expected filesystem and launcher behavior from `process.platform`.
- Add Linux test-environment instructions for `ripgrep`, `fd-find`/`fd`, and a non-root test account.
- Bump every public Euler package together from `0.1.0` to `0.1.1`; regenerate package artifacts and publish in dependency order.

## Acceptance criteria

- The external-editor test passes on Linux with a quoted Node executable.
- Web-access tests pass on both Windows and Linux.
- `./test.sh` passes on Linux under a non-root user with `rg` and `fd` present.
- A clean temporary installation of `euler-agent@0.1.1` reports version `0.1.1` and starts `--help` successfully.
- GitHub receives a `v0.1.1` tag only after these checks pass.
