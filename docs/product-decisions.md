# Euler Agent 产品方案与已确认决策

> 状态：历史决策记录；正式实现以已批准设计规格为准
> 日期：2026-08-28  
> 基础项目：[PI](https://github.com/earendil-works/pi)

## 1. 产品目标

创建一个名为 **Euler**、拥有独立品牌、独立 CLI/TUI 界面和独立系统提示词的终端 Agent。

第一版不从零重写 Agent 核心，而是以 PI 为基础进行发行和维护，在尽量保持 PI 默认行为、扩展生态和功能完整度的前提下，加入本产品自己的外壳与少量核心能力。

第一版目标不是最小化 MVP，而是实现与 PI 基本齐全的功能对等。

本地开发与人工验收以 Windows 为主。第一版必须保证 Windows x64 可用；同时利用 CI 构建和测试 PI 已支持的其他平台，验证通过的 macOS、Linux 和 ARM64 产物可同步发布，不要求开发者本人持有对应设备。

分发方式已确认：

- 发布 npm 全局安装包，安装后提供 `euler` 命令。
- 发布无需 Node.js 的独立可执行文件。
- Windows x64 是首发的强制发布目标。
- CI 尝试生成 Windows ARM64、macOS x64/ARM64、Linux x64/ARM64 产物；只有自动构建和测试通过的产物才发布。
- 非 Windows 产物失败时不阻塞 Windows 首发，修复后补发。
- 构建与打包流程优先复用 PI 现有的 Bun standalone binary 方案。

## 2. 总体技术路线

采用“PI 下游发行版 / 轻量 Fork”方案：

- 复用 PI 的 Agent 核心、会话系统、模型适配、工具系统、TUI 和扩展机制。
- 修改品牌、命令名称、CLI/TUI 外观、系统提示词和默认配置。
- 将产品自身的改动控制在较小范围，方便持续合并 PI 上游更新。
- 遵守 PI 的 MIT 许可证，保留必要的许可证和版权说明。
- 不重新设计 PI 已经成熟且无需改变的接口。

上游同步策略：

- 每个 Euler 版本锁定一个明确的 PI commit 或 release tag。
- PI 发布新版后，由维护者人工审核变更并合并。
- 合并后必须通过 Euler 品牌、系统提示词、Extension 兼容、联网能力和跨平台回归测试。
- 未通过审核与测试的 PI 更新不得自动进入 Euler 发布版本。

## 3. 默认核心工具

与 PI 保持一致，默认提供四个本地操作工具：

| 工具 | 功能 |
| --- | --- |
| `read` | 读取文件内容 |
| `write` | 创建文件或完整写入文件 |
| `edit` | 对现有文件进行精确局部修改 |
| `bash` | 执行终端命令 |

在 Windows 上需要评估是否将 `powershell` 作为适配层或附加工具，但不改变上述四个默认核心能力的语义。

## 4. CLI / TUI 外壳

产品拥有自己的终端交互界面，包括：

- 独立产品名称、命令名称和启动入口。
- 独立 Logo、欢迎页、颜色、主题与状态栏。
- 独立帮助信息、错误提示和用户文案。
- 独立配置目录和环境变量前缀。
- 保留 PI 已有的键盘操作、会话交互和命令能力。

`/resume`、`/new`、`/model` 等属于程序内置命令，不属于 Prompt Template 或 Skill。

已确认：

- 正式产品名称为 **Euler**。
- CLI 启动命令为 `euler`。
- 主输入区域采用极简圆角框：单层细边框、低信息密度、突出当前输入内容。
- 输入框下方可以显示少量快捷键或模式信息，但不增加标题栏和双层边框。
- 完整 TUI 保留 PI 的信息结构和键盘交互，使用 Euler 欢迎区与品牌文案。
- 工具调用在对话流中以紧凑卡片显示，成功、失败和运行中状态清晰可辨。
- 自动搜索摘要与来源直接显示在终端对话流中。
- 底部状态区显示当前模式、模型、分支和剩余上下文等必要信息。
- 全局配置目录使用 `~/.euler/agent`，不直接读取 `~/.pi/agent`。
- 环境变量统一使用 `EULER_*` 前缀，不兼容或读取 `PI_*` 别名。

## 5. 系统提示词

产品使用自己的默认系统提示词，用来定义：

- Agent 的身份和行为原则。
- 默认工作方式。
- 核心工具的使用规则。
- 安全边界和交互风格。
- 项目上下文和用户指令的优先级。

系统提示词需要作为源码或可查看资源透明保存，不将会影响 Agent 行为的重要规则隐藏起来。

已确认：

- 以 PI 原始系统提示词为基线，不完全重写 Agent 的默认行为。
- 将 PI 身份和品牌内容替换为 Euler。
- 增加 `web_search`、`fetch_content` 等联网工具的用途、调用边界和外部内容安全规则。
- 其余修改保持克制，避免无意改变 PI 的工具选择、编码和会话行为。
- 用户可以通过普通模式向默认提示词追加自定义规则。
- 高级用户可以完整覆盖系统提示词，但界面需要明确提示风险。
- 每次修改自动保留上一版本，并提供一键恢复 Euler 默认提示词。
- 保存前检查空内容、无效模板变量和无法解析的配置。
- 自定义提示词加载失败时自动回退默认版本，并向用户说明原因。

系统提示词的具体文案尚未定稿。

## 6. Prompt Template

保留 PI 的 Prompt Template 格式与加载方式，不另造不兼容格式。

Prompt Template 是用户保存的 Markdown 提示词快捷方式。例如文件名为 `review.md` 时，可通过 `/review` 调用。它可以包含 `$1`、`$@` 等参数占位符。

它与 `/resume` 等内置命令不同：

- 内置命令会执行程序逻辑。
- Prompt Template 会展开为一段发送给模型的提示词。

目标是兼容已有 PI Prompt Template，使用户可以直接迁移和使用。

## 7. Skill

Skill 是按需加载的专业操作手册，通常由 `SKILL.md` 和可选的脚本、模板、参考资料组成。

已确认：

- 主程序默认不捆绑官方 Skill，行为与 PI 保持一致。
- 兼容 PI 可用的 Agent Skills 格式。
- 用户安装的 Skill 必须透明、可查看、可禁用和可卸载。
- Skill 不得以不可见的隐藏提示词形式偷偷影响 Agent。
- 后续可以建立独立的可选 Skill 仓库或 Package，但不随主程序默认启用。

## 8. TypeScript Extension

完整保留 PI 的 TypeScript Extension 机制和 `ExtensionAPI`，第一版不重新设计、不删减、不制造私有的不兼容版本。

Extension 是真正执行代码的插件，可用于：

- 注册新工具和命令。
- 监听或修改 Agent 生命周期事件。
- 改变界面和状态展示。
- 接入外部服务。
- 扩展会话与工作流行为。

因为 Extension 以当前用户权限执行代码，安装和启用第三方 Extension 时需要明确展示来源与安全提示。

## 9. Package

保留 PI 的 Package 机制。Package 是扩展资源的分发容器，可以组合：

- Skill
- TypeScript Extension
- Prompt Template
- Theme

已确认：

- 主程序不预装默认官方 Package，与 PI 保持一致。
- 支持查看 Package 内包含的全部资源。
- 支持启用、禁用和卸载 Package。
- 尽量直接兼容 PI Package。

Package 本身不是另一套 Skill 系统；它只是可以携带 Skill。

## 10. 内置互联网搜索与网页读取

在 PI 默认能力之外，第一版增加产品级联网能力。Euler 随主程序集成 MIT 许可的 [pi-web-access](https://github.com/nicobailon/pi-web-access)，将其从 PI 的第三方 Package 提升为 Euler 的内置联网模块。

这项能力定义为主程序内置功能，而不是默认 Skill。上游原版 PI 并不自带它。

计划提供的核心工具语义：

| 工具 | 功能 |
| --- | --- |
| `web_search` | 根据关键词搜索互联网，返回标题、链接、摘要等结构化结果 |
| `fetch_content` | 读取网页、GitHub 仓库、PDF 或受支持的媒体内容 |
| `get_search_content` | 按需读取已缓存的完整搜索内容，减少上下文占用 |
| `source_check` | 对搜索来源和论断进行结构化核验 |

同时保留以下用户命令：

- `/websearch`：打开搜索整理界面，手动搜索、筛选结果并确认摘要。
- `/curator`：启用或关闭搜索整理工作流。
- `/search`：浏览当前会话中保存的搜索结果。

交互规则：

- Agent 自动调用 `web_search` 时不打开浏览器或搜索整理界面，结果直接返回 Euler 终端。
- 只有用户主动输入 `/websearch` 时才打开搜索整理界面。
- 自动搜索默认使用 `auto-summary` 工作流，在终端返回总结和来源链接。
- 用户可通过 `/search` 查看完整搜索结果，通过 `/websearch` 进行人工筛选。

设计原则：

- Agent 可以像调用 `read`、`bash` 一样直接调用联网工具，不需要先加载 Skill。
- 默认搜索路由不得调用收费 Provider，也不得要求用户提供 API Key。
- 默认搜索顺序为：零配置 Exa MCP → 免密 DuckDuckGo；只有前者失败时才进入后者。
- MCP 只是 Exa 的内部连接方式，不是 Euler 搜索功能的统一依赖；DuckDuckGo 路径使用普通 HTTP。
- 对 Agent 和用户只暴露统一的 `web_search` 接口，默认不要求用户理解或单独配置 MCP。
- 收费 Provider 即使被包内代码支持，也必须保持禁用，不能自动产生费用。
- 用户未来如主动配置其他 Provider，必须由用户明确启用。
- 联网模块默认开启，不提供联网总开关或分项开关。
- API Key 若由用户主动配置，只能保存在安全配置位置，不写入会话、日志或项目文件。
- 工具返回结构化数据，并限制正文长度，避免无控制地占用上下文。
- 搜索和网页读取需要有超时、重试、错误提示和速率限制处理。
- 搜索结果是外部不可信内容，不能被当成系统指令执行。

实现边界：

- 第一版以 `pi-web-access` 当前稳定接口为准，不重新实现同名工具和搜索整理界面。
- 保留 `pi-web-access` 的 MIT 许可证和版权声明。
- 对上游版本进行锁定和兼容测试，升级时审核 Provider 路由、隐私和收费行为是否发生变化。
- Firecrawl 不作为 Euler 的默认依赖或默认 Provider。

这会使本产品在默认功能上比 PI 多出联网能力，是一项有意保留的差异。

## 11. PI 功能对等范围

第一版计划保留或复刻以下能力：

- 多模型与多 Provider 支持。
- 模型登录、选择与切换。
- Thinking Level 调整。
- TUI、Print、JSON、RPC 和 SDK 使用方式。
- 会话新建、恢复、树状分支、Fork、Clone、Compact、导入、导出和分享。
- 项目上下文文件与全局配置。
- Prompt Template、Skill、Extension、Theme 和 Package 加载机制。
- 自定义快捷键和主题。
- PI 已有的可选文件查找与终端工具能力。

模型配置交互已确认：

- 完全沿用 PI 的登录与模型选择机制。
- 用户通过 `/login` 配置 Provider，通过 `/model` 选择模型。
- 首次启动不显示额外配置向导。
- 不自动读取或导入用户现有的 PI 配置。

具体命令表和逐项验收标准将在技术设计阶段从对应 PI 版本生成，避免遗漏或凭印象复刻。

## 12. 明确不作为默认内置功能的项目

除非后续重新决定，以下能力不作为第一版主程序的默认内置模块：

- 官方默认 Skill 包。
- 官方默认 Package。
- 默认 MCP 系统。
- 默认 Subagent 系统。
- 默认 Plan Mode。
- 默认 Todo 系统。
- 内置沙箱。
- 每次操作都弹出的权限确认框。

这些能力将来可以通过 Extension、Package 或独立版本演进加入。

## 13. 安全与透明性

- 项目信任不等于操作系统沙箱。
- `bash`、Extension 和第三方脚本默认拥有当前用户可用的权限。
- Skill、Prompt Template、Extension 和 Package 的来源、内容与启用状态必须可查看。
- 第三方网页内容、仓库内容和工具输出一律按不可信输入处理。
- 涉及密钥的配置必须脱敏展示，禁止进入模型上下文或普通日志。
- Euler 不收集匿名安装、更新或使用统计，也不发送项目、会话或工具使用遥测。
- 版本检查仅提交当前版本及发布通道所必需的信息，不附带持久设备标识。
- 启动时发现新版本只显示提示，不自动下载或安装。
- 用户主动执行 `euler update` 后才更新主程序；Package 更新继续沿用 PI 的相应命令语义。

## 14. 已收敛的实现规则

- 默认系统提示词按锁定 PI 版本生成 Euler 差异稿，并通过差异审查保护行为一致性。
- CLI/TUI 以已批准结构为标准，具体色值和间距通过 Theme Token 微调。
- 模型 Provider 和模型目录完整继承锁定 PI 版本，不维护 Euler 私有 Provider Fork 或私有默认模型。

## 15. 当前验收原则

第一版完成时应满足：

1. 用户感知到的是独立产品，而不是简单改名的 PI 启动脚本。
2. PI 的核心 Agent 行为和主要功能可以正常使用。
3. 已有 PI 的 Prompt Template、Skill、Extension 和 Package 能以尽可能低的迁移成本使用。
4. `pi-web-access` 的搜索与内容读取工具作为 Euler 内置能力可被 Agent 直接调用。
5. 所有影响 Agent 行为的本地资源均透明、可检查。
6. 产品自身改动与 PI 上游代码尽量隔离，能够持续吸收上游更新。

## 16. 已确认的发布前测试环境

除自动 CI 隔离测试外，Euler 第一版发布候选需要在一台真实 Linux 服务器进行干净安装测试：

- Ubuntu 24.04.3 LTS
- x86_64 / amd64
- Linux 6.8 内核
- 2 vCPU、约 4 GB 内存
- KVM 虚拟化

服务器公网地址不写入产品规格或代码仓库。连接测试必须由用户另行明确授权并提供认证方式。

服务器验收同时覆盖：

- 从发布候选 npm 压缩包进行干净安装并验证 `euler` 命令。
- 下载 Linux x64 独立可执行文件，在没有项目开发依赖的环境中运行。
- 验证 `--help`、`--version`、TUI 启动、配置目录、会话保存和免密搜索路径。

此服务器目前只确定用于第一版验收；后续版本的服务器测试策略以后另行决定。
